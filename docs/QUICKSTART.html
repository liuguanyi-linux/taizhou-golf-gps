朋友测试：放点、测距、导出

第一次打开

直接打开 https://liuguanyi-linux.github.io/taizhou-golf-gps/ ，无需登录。也可下载并解压完整 ZIP，运行 node scripts/serve.cjs，打开终端给出的本机网址。首页的“打开球洞工作台”是统一入口，不需要在两张网页之间来回编辑。

  • 选择第 1 洞，切换“虚拟图”，点“编辑本洞”。窄屏先点“点位工具”展开工作台。
  • 在“标点测距”填名称，例如“球车 A”，选择球车类型，点“在虚拟图放置新点”，然后在图片上点一下。已有命名点可以拖动。
  • 放置第二辆球车 B。选择 A 为出发点，勾选 B、果岭旗、Tee 等目标；也可选其他球洞的目标。距离表会随点位改变。
  • 图片支持现有缩放/移动操作。缩放只改变显示，不改变底图原生像素与经纬度记录。
  • “设备预览”在同页打开；“返回虚拟图”回到编辑。模拟位置不代表已获得真实 GPS，也不代表刚放置的每辆命名球车在自动移动。
  • 到“设备数据”导出测试包或 GeoJSON，保存备份。当前草稿不会自动上传仓库。

想获得可靠的图上任意点坐标，先校准

进入“地图校准”，将虚拟图与实际地图中同一地物配对。至少 3 个不共线点，建议 5 个以上分布于起点、果岭及两侧，记录现场测量 / 影像选点等来源。独立检查点不参与拟合。应用并保存，再检查图内多个位置的换算结果。

第 11 洞默认控制点退化时拒绝新标点，是防止输出看似精确的错误坐标。补足横向控制点后重新校准。默认图像是美术图，不保证任意像素自然对应准确实地坐标。

接入真实车辆

从工作台导出或复制已有车辆完整 ID，客户程序定期提交该车辆 WGS84 坐标、时间戳、可用时的精度。参考技术文档中的 GolfDevicePoints.updatePositions。车辆 A 和 B 必须使用各自 ID；不能用示例 ID 当真实车辆。

浏览器“实时 GPS”只读取打开网页的那台设备，不会凭空获得朋友的其他球车坐标。多车数据需要车载设备 → 客户服务 → 本工作台的接入程序；这一网络服务不在当前包内。

任意点距离表是地表直达距离，不是车道行驶距离。设备预览中的“沿路线剩余距离”需要可靠车道折线；当前单独路线文件只有第 1 洞且未现场复核，不代表所有 18 洞车道都已完成。

给开发朋友的最小文件组合

  • 完整 ZIP：直接运行页面与所有图片。
  • 现场完成校准后导出的测试包：最新点位、稳定 ID、控制点、模型、坐标来源。
  • TECHNICAL.md：接口约定和限制。

仓库自带的 baseline 包只是初始磁盘数据，不包含你此刻浏览器里尚未导出的修改。请区分“源码发布”和“个人编辑数据备份”。
