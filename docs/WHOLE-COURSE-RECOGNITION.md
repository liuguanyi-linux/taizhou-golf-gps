# 整场识别与逐洞归属：第一阶段

更新：2026-09-15。当前已实现候选接入、空间归属建议、人工核对及共享坐标制图；**尚未接入整场卫星语义识别模型，不是全自动测绘系统**。

## 使用入口

1. 从地图页选择球场，进入同一个球洞编辑器。
2. 展开“公开地图读取与导出（详细工具）”。
3. 点击“读取公开地图并生成…”：读取已有公共地理要素，并分析整场归属。
4. 选择正确的闭合球场边界。右侧显示来源洞号、中线候选、待归属项和冲突数量。
5. 用“定位”对照地图核对类型、轮廓和洞号，再勾选要导入的项。中线匹配建议不会自动勾选。
6. 点击确认生成，只有已勾选项写入当前本机项目。切换球洞可继续编辑；虚拟图和 GPS 共享这些 WGS84 节点。
7. 回到“球场制作流程”，批量生成缺少的高清图。缺少必要地理要素的洞明确跳过，不虚构地形。

“整场分析 · 逐洞归属”中的“检查当前全场缺失项”可直接检查已有项目，不必再次访问公开地图。

## 自动分析依据

`course-workspace/course-recognition.js` 是独立 UMD 模块，浏览器与 Node 测试使用相同实现。

- 来源有合法洞号：建议沿用，但仍需人工核对。项目没有该洞号时，不换成邻近洞号。
- 来源没有洞号：使用现有球洞中线，或候选中已经编号的击球中线，提出空间归属建议。
- 同一个洞存在不同中线时，排除该洞的中线锚点。长度小于 30 m 的线不作为整洞中线。
- 至少存在两条不同洞的可用中线，才进行竞争比较，避免一条线吸收整场地物。
- 比较要素所有原始节点到每条中线的距离，以最大距离评分；不移动坐标，不按质心吸附。
- 第一候选距离不超过 60 m，且第二候选至少远 15 m、距离至少为第一候选的 1.5 倍时，才提出唯一走廊候选。
- 以上是保守的工程筛选阈值，不是学习模型的置信度，不是测量精度，尚未通过跨球场统计评估。大果岭、宽球道、交叉球洞可能仍需手动归属。
- 水域、长草区、球车道可能跨洞共享；中线涉及方向，旗位涉及目标定义。这些无洞号要素不自动归属。
- 单值字段的多候选冲突、现有编辑冲突、已导入要素均标记，不能自动覆盖。
- 空间评分预算为 2,000,000 次节点—线段比较，超出部分保持待归属，避免大数据卡死。

边界过滤沿用现有的“所有节点位于边界内”检查；它不是完整的线段裁剪或多边形拓扑验证。候选跨越凹形边界、形状自交等仍需核对。不会为了通过检查强行裁剪或改变源轮廓。

## 识别结果接入格式

支持文件或粘贴 GeoJSON，最多 5 MB / 1000 个 Feature / 40000 个坐标节点。只在本地浏览器解析，不上传设备位置或源影像。

最小外层结构：

```json
{
  "type": "FeatureCollection",
  "coordinate_system": "WGS84",
  "source": {
    "name": "影像或测绘成果名称",
    "method": "生产该候选的方法或模型版本",
    "license": "实际许可信息",
    "accuracy_m": null
  },
  "features": []
}
```

不附伪造示例坐标。每个 Feature 应具备唯一 `id` 和正确的 `geometry`：

| properties.kind | geometry | 含义 |
| --- | --- | --- |
| course | Polygon | 用于确认归属的闭合球场边界 |
| hole / centerline | LineString | 击球中线，不作为球车道 |
| fairway | Polygon | 球道 |
| green | Polygon | 果岭轮廓，不是当日旗位 |
| tee / teebox | Polygon | 发球区轮廓，不会虚构不同颜色 Tee |
| bunker | Polygon | 沙坑 |
| water | Polygon | 水域 |
| cartpath / cart_path | LineString | 球车道 |
| pin | Point | 来源旗位，必须自行核对 |

可选 `properties.hole` 为 1–72 整数；无编号时省略。`properties.name` 用于展示。必须显式声明 WGS84；不会把 GCJ-02、投影米坐标、像素位置或未知坐标系直接当作 WGS84。单环 Polygon 才能进入当前编辑器；带孔、多面不能丢弃内环后冒充单面，需另行处理。

此格式是模型输出的接入契约，**不是模型推理端点**。普通 PNG/JPEG 或未分类分割掩膜不能直接导入为有效地图。

## 数据与发布边界

- `map_sources` 保存 Feature ID、来源属性、来源方法及原始几何。
- 非 OSM 来源不再错误标记为 OpenStreetMap 或 ODbL；保留原声明来源和许可。
- `recognition_review` 保存本次确认的洞号、类型、建议洞号及确认时间。它是本次批次记录，不是完整历史账本。
- 候选归属报告可单独下载，描述分析时的建议，不代表尚未提交的人工选择，也不是精度报告。
- 所有生成参考点和确认记录的验证精度保持 `accuracy_m: null`。源文件的精度声明只作为来源元数据，不视为已验证。
- 写入本机项目副本，不调用朋友后台发布接口；不会自动提交 Git 或发布网站。
- Leaflet 编辑保存可能去掉闭合面最后一个重复顶点，不移动其余节点；原始闭合环仍在来源记录中保留。

## 第一阶段验收

自动测试：`node tests/course-recognition-test.cjs` 和 `node tests/generation-ui-test.cjs`；纳入 `node scripts/check.cjs`。

浏览器使用单独创建的“整场归属流程验收（合成数据，非真实球场）”项目：

- 两条有编号中线、三个无洞号地物和一个共享水域输入；三个地物建议归属第 1 洞，水域保持待归属。
- 建议项默认不勾选；确认后只保存两个中线和三个地物，没有添加水域或虚构第三洞。
- 刷新后，果岭节点、参考点及来源记录与保存值一致。
- 发球区参考点到果岭参考点显示 368.9 m；这是合成坐标的计算验收，不是现场测量。
- 批量制图生成第 1 洞 1000 × 3072 图片；第 2、3 洞缺少必要区域，明确跳过。
- 在新图上实际放置模拟球车，生成 WGS84 点，并显示到果岭的距离。

这些验证证明流程和数据联动，不证明自动识别真实球场的准确率或实地精度。

## 后续整场卫星识别仍需完成

2026-09-15 进展：已增加 [CLIPSeg 本机影像候选试验](LOCAL-IMAGE-RECOGNITION.md)，并实际运行卫星图推理。它补上了模型输入与 WGS84 候选链路，但通用模型对当前影像存在漏检，仍不能代替下面的整场识别、领域评估和现场核验。

1. 选择允许处理的地理配准影像来源，记录分辨率、采集时间、许可和坐标系统。
2. 部署影像分割及地物分类模型，处理阴影、树木遮挡、相邻球洞、车道与步道混淆；不能只根据颜色连通区域判断类型。
3. 将掩膜按原始地理变换转为坐标候选，保留多面、孔洞和未识别区域，人工审核后接入本阶段流程。
4. 根据官方攻略图 / 已核对中线确认实际洞号，验证方向，不依赖地图距离猜测官方编号。
5. 在多个不同球场测量类型、边界和归属误差，再决定哪些项可减少人工确认。
6. 实地精度使用独立测量检查点，沿用既有精度检查工具；模型分数不替代米级误差。

技术依据：地理影像分割可使用 [SamGeo 官方流程](https://samgeo.gishub.org/examples/satellite/)；像素到地理坐标转换见 [GDAL geotransform](https://gdal.org/en/stable/tutorials/geotransforms_tut.html)。两者都不自动保证球洞类别、官方编号或地面精度。
