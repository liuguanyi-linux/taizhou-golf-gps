# 球场持续编辑与交付流程

2026-09-13 · 本地功能更新，未发布到原站或 GitHub。

## 四步入口

编辑器左上统一提供：

1. 检查 / 补充地图要素：读取公开数据并要求确认球场边界、洞号、类型；不是从名称虚构全部球洞。
2. 批量生成缺少的高清图：只处理具有可制图几何、尚无图片的球洞。原有图片不覆盖；需要更新时进入详细工具，明确选择替换并保留上一版。
3. 打开本洞 · 编辑 / GPS：调用同一图片与坐标编辑器，已有配准和点位继续使用。
4. 交付前检查 / 下载：列出逐洞缺失和相对上一次本机导出快照的差异，确认后生成完整包。

“本洞下一步”根据本洞状态提示补地图、生成图、配准、重绘或打开编辑。详细工具折叠保留，不移除原来功能。

状态分为 `missing_geometry`、`needs_image`、`needs_registration`、`needs_regeneration`、`ready_for_review`。最后一个只表示图片和数学配准可供检查，不代表球洞要素齐全、图片资源绝对可用或现场精度达标。资源是否可读取在导出时进一步验证。

清单检查洞界、球道、果岭、发球区、球车道、旗位记录和 PAR。已有坐标记录不等于现场测量；所有状态仍 `field_verified: false`。

## 同一球场不再反复新建

`GreenBookSource.existing(venueID)` 按明确的 `source_import.type = greenbook_public` 与 `source_import.venue_id` 查本机项目，按照保存时间、版本号排序。兼容旧版以 `source_project_id` 记录来源的已保存项目，也检查以原球场编号保存、尚未列入自定义目录的旧基线草稿。

- 从原站搜索结果选择已做过的球场，会优先提供“继续已有球场项目”。不重读和覆盖现有编辑；没有连上原站时也可从本机项目列表继续。
- 多个已有副本可以手动选择。不同球场编号、同名球场不会自动合并。
- 只有“另建独立副本…”显式创建新项目，并重新读取原站资料。原有项目保留。
- `importLocal` 本身也默认复用已有 ID，重复点击不会连续创建相同来源副本；`forceNew: true` 才强制新建。
- 这不是原站版本合并工具。现阶段不会自动把原站后来的改动合并进本机旧项目，避免覆盖用户编辑。

## 交付包与差异

沿用 `golf-project/1` 可移植包，新增顶层 `delivery_review`：

- 逐洞制作状态与缺失项；
- 新增、修改、移除、未变化洞号，以及球场元信息变化；
- 当前快照 `golf-delivery-snapshot/1`；
- `published: false`、`field_verified: false`。

快照以稳定键序列化后的 SHA-256 比较每洞数据；保存版本号和普通保存时间变化不会产生元信息差异。每洞包含自由点、图片引用及配准、实测记录和扩展数据，其变动会进入差异列表。

对比基线存储在本机 `golfmap.delivery-review.<projectID>`，只在包成功生成并发起下载后保存。软件不能确认浏览器最终保存成功，界面会要求检查下载文件。这不是服务器发布历史、数字签名或现场验证证明。

下载前需要确认缺失项和隐私。包包含球车测试位置、实测记录、当前和上一版图片等；**不会自动删除敏感信息**。检查后项目发生变化会要求重新检查。浏览器只自动发起一次完整包下载，检查报告同时包含在包中，并提供单独下载链接。

换浏览器或电脑时，下载后在地图页导入完整项目包。仍然是独立副本，不会云端同步。浏览器清理存储前必须保留完整包。

## 仍需完成的后续能力

真正的在线发布需要选定用户自己的持久化后端、访问控制和版本接口，之后才可把草稿提交为多人或设备可读版本。当前没有此接收端，不能把下载称为上线。实际定位精度仍需有质量依据的现场点位及独立检验；详见 [高清与实地精度](HD-AND-FIELD-ACCURACY.md)。
