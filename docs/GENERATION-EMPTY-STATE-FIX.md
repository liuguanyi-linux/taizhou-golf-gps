# 2026-09-14：生成按钮与缺失数据补绘流程修复

## 提示词来源及应用

按用户要求，通过 prompts.chat 检索并读取 Mike 的 **Debugging Detective**。
提示词 ID：`cmriqkb6f0001jo09fr9gltlg`，站内 slug：`debugging-detective`。
来源：[prompts.chat 调试提示词目录](https://prompts.chat/tags/debugging)。

采用它的根因诊断方法，而不是让提示词代替事实证据。针对本任务的执行要求：

> 复现生成按钮无反应，区分网络读取、边界筛选、勾选归属和保存状态；核查实际输入与事件处理；修复可见反馈及缺失数据入口；用正向、空数据、错误和重复点击测试验证。保留 WGS84 原始坐标和用户已有编辑，不把未知精度写成实测。

## 根因

1. 右侧生成只处理已读取的候选，不再请求地图服务器。零候选时原按钮被 disabled，却仍使用绿色外观，也没有就近显示具体禁用原因。
2. 原逻辑只检查候选数量，没有随勾选、洞号、类型变化更新可提交状态。
3. 被边界检查排除的要素原来统一写成“范围外”，但实际也可能仅部分跨界。
4. 缺失逐洞源数据的补绘入口藏在左侧折叠项，确认面板没有后续行动入口。

南山案例此前读取到 26 个水域面、零个通过全部节点边界检查的候选；不能据此生成 18 个球洞，也不能用卫星照片存在来证明已有逐洞矢量数据。

## 本次修改

- 零候选、未勾选、未归属、处理中分别显示按钮状态及原因；不可用按钮灰显。
- 显示源要素类型数量；排除项表述为“未通过边界节点检查（可能跨越边界）”，不误称全部完全在外。
- 空结果提供洞号选择和球道、果岭、发球区、球车路线补绘按钮，接入现有卫星地图 Geoman 工具，不复制数据模型。
- 生成前让浏览器呈现处理中状态，锁定重复操作；保存异常就近显示且允许重试；已导入项不可重复勾选。
- 原坐标导入约束不放宽；没有实现自动卫星分割、自动裁剪跨界多边形或实测精度提升。

## 验证

`node --test tests/generation-ui-test.cjs` 覆盖实际 UI 处理函数：

- 仅有未通过边界检查的水域：禁用生成、显示缺失提示，按指定洞号启动补绘。
- 无编号要素：勾选后仍禁用，指定洞号才可生成；重复点击只保存一次。
- 保存失败：显示原因、恢复可重试状态，不显示成功。
- 无边界、取消边界选择、读取离线：不写项目并给出反馈。

这些测试纳入 `node scripts/check.cjs`。已有地图生成、GPS 和坐标配准回归测试继续运行。单元测试不是现场坐标精度认证。

实际浏览器验收：从原站检索 `cn0000055` 南山国际高尔夫俱乐部，建立独立本机草稿；读取到 26 个水域，选择 `way/113558968` 后确认零可导入要素、按钮禁用、空状态及四个补绘入口可见。选择第 3 洞并点击“补绘球车路线”，当前洞切到 3，卫星图进入 Line 绘制状态，显示完成绘制工具。没有绘入假设路线，也没有发布球场数据。

## 用户操作

读取完成后，先选择球场边界。有候选时勾选并确认洞号；没有候选时，在右侧选择要补绘的洞，然后点击“补绘果岭”等按钮。在卫星图沿实际地物点击完成线或面，之后切换“虚拟地图 · 可编辑”。车道使用线工具，不以击球中线代替。当天旗位和有颜色的 Tee 点仍需按实地信息单独放置。
