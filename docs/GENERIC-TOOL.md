# 通用球场项目工具：操作、数据与验收

版本：2026-09-11，本地开发版。本文取代把每个球场做成独立页面的使用方式；旧模块保留兼容，不删除已有数据和图片。

## 1. 这次交付是什么

一个工具管理多个球场项目。新球场无需在编辑器中写专用分支：通过地图页新建或导入，设置洞数，使用相同的地图绘制、图片配准、任意点编辑、GPS 测距与项目包导出流程。

本地入口：`http://localhost:3034/cn/map/`。运行 `node scripts/serve.cjs`；不启动或改动原站的 3030、8088 和 Docker。

这不是已经完成测绘认证的全自动生产系统。名称查询只找到球场位置，不会自动识别全部洞号、球车道和准确边界。现阶段的自动虚拟图生成是根据已建立地理几何导出 SVG；高清美术图由用户上传或使用已有资产，工具不会凭空补出可靠 GPS。

## 2. 新球场固定操作流程

更新：默认搜索现在连接原网站 GreenBook 球场库。输入部分关键词 → 选择原站结果 → 查看实际有数据的洞数 → “接入为独立项目并编辑”。已有地理数据自动带入，无须手工下载 JSON；原站为空时只建立有明确待补标记的空白洞位。实现、安全边界及实测结果见 [原站接入说明](GREENBOOK-CONNECTION.md)。下述外部名称定位现在是备用入口。

1. 在地图页输入球场名称查询，或展开“添加其他球场 / 导入已有划分”，在地图选择位置。新建时填写名称与 1–72 洞，进入该项目编辑器。
2. 有旧编辑器 JSON 或 WGS84 GeoJSON 时，优先导入。每次导入建立独立项目 ID，不覆盖已有项目。选洞后，同一页面切换“实景地图”“虚拟地图 · 可编辑”“本洞图片 / 配准”“GPS 测距”。
3. 在实景地图用原有点、线、面工具绘制 Tee、果岭、球道、水域、周界与车道。球车行驶路线单独绘制，不拿击球中线代替。每条线的节点顺序就是模拟方向，应从出发端画向到达端。
4. 打开“本洞图片 / 配准”，上传 PNG、JPEG 或 WebP。选择至少 3 个不共线的对应地物点，建议 5 个以上分布到整个球洞。点“去地图选择对应位置”，点地图上的地物，回到图片再点击同一地物；也可输入 WGS84 经纬度。留出独立检验点，不让它参与拟合。
5. 有效配准后，在“图片操作”中选“放置球车”或“放置目标点”，填名称并点击图片。切回“移动视野 / 拖动已有点”可拖动。Tee、果岭旗和路线也有对应操作。绿色覆盖范围之外禁止把图片点击转换成 GPS。
6. 图片中可直接开启“模拟本洞车道”或设备“实时 GPS”。更复杂的球车 A→球车 B、球车→其他洞 Tee 测距，在顶部“GPS 测距”中选择起终点，无需新开网页。任意点之间显示地表直线距离，不把它称为沿道路里程。
7. 完成后点“保存本机数据”。展开“球场项目 · 保存 / 图片打包 / 检查”，下载完整项目包。客户从地图页导入此文件，即可恢复包含图片的独立副本。

图片放大只影响画布：滚轮或 ＋/− 以视口中心缩放，拖空白平移，“全图”恢复完整图像。左侧 GPS 与编辑控件不跟随图片缩放，工具栏不叠在图片内容上。

## 3. 项目与资产格式

| 内容 | 格式 / 存储 | 用途 |
| --- | --- | --- |
| 球场数据 | `golf-course/1`，localStorage | 名称、中心、各洞点线面、路线、点位及图像描述 |
| 完整项目 | `golf-project/1` JSON | 包含 course、assets、导出时间，可跨浏览器导入 |
| 原图 | IndexedDB `golf-project-assets` / `images` | 以内容 SHA-256 标识；不写远程后台 |
| 图像对应关系 | `holes[].visual.controls` / `checkpoints` | 图片像素坐标与 WGS84 经纬度 |
| 设备点 | `holes[].device_points` | 稳定 ID、name、kind、coordinate、source、accuracy_m |
| 兼容草稿 | 逐洞 localStorage 草稿 | 与已有查看器协作；旧编辑器未识别字段合并保留 |
| 内置项目目录 | `course-workspace/catalog.json` | 仅数据描述现有基线和图片来源，无球场专用编辑逻辑 |

最小结构示意（示例坐标不是实际球场）：

```json
{
  "format": "golf-project/1",
  "field_verified": false,
  "course": {
    "schema_version": "golf-course/1",
    "name": "自定义球场",
    "coordinate_system": "WGS84",
    "center": [121.1, 31.2],
    "holes": [{"n": 1, "tees": {}, "device_points": [], "cart_route": []}]
  },
  "assets": {}
}
```

有图片的 `visual` 包含 `asset_id`、实际像素 `width/height`、对应点数组。每个对应点包含 `pixel:{x,y}` 与 `coordinate:[longitude,latitude]`。完整包的 assets 按 asset_id 保存 raster data URL；禁止 SVG/脚本或远程 URL 作为上传图片。单图上限 20 MB、5000 万像素；文件导入上限 256 MB。普通 JSON 备份不包含 IndexedDB 图片，跨设备务必用“完整项目包”。

每次保存递增 revision，用于识别当前快照，不代表完整历史版本库。长期保存仍需导出备份；浏览器清理、不同域名/端口、隐私模式会影响本机存储。`localhost` 与 `127.0.0.1` 也不是同一个草稿空间。统一使用同一入口，迁移前先导出。工具没有云端多人协作或自动远程备份。

## 4. 地理导入与 GPS 对接

GeoJSON 导入要求 FeatureCollection；每个 Feature 的 `properties.hole` 是 1–72 的洞号，`properties.feature_type` 指明用途。经纬度顺序为 `[经度, 纬度]`，WGS84 / EPSG:4326；不猜测 GCJ-02、BD-09 或投影坐标。

支持：Point（tee 配 color、flag、tree、其他自定义点）、LineString（centerline、cart_drive_route、cart_path、path、creek、ditch、out_of_bounds、fence、penalty_area_red/yellow）、Polygon（hole_perimeter、green、tee_box、fairway、green_fringe、rough、bunker、water、bridge）。当前不支持 Multi*、带内环的 Polygon 或重复的主面/主线，明确报错，不悄悄丢弃；原始导入 GeoJSON 也保存在项目中。

浏览器 Geolocation 连续更新当前设备位置；GPS 多车数据入口接收 JSON/CSV 快照，用设备 ID 更新点位。它不是已经接好客户球车平台的消息服务器。HTTP 本地调试可用 localhost；远程设备定位需要 HTTPS、用户授权和设备可用的定位服务。GPS 位置不强制吸附车道，模拟位置明确标记为“非实测”。

客户设备接入还需要其协议说明、设备 ID 规则、时间戳、精度字段、发送频率及接口认证。现阶段可交付 WGS84/GeoJSON 与完整项目包，真实设备通信、离线部署和场地精度尚未验收。

## 5. 精度与范围

图片只是表现层，WGS84 才是点线面数据。`registration.js` 拟合图片与地理坐标的对应关系，并限制控制点凸包覆盖；拟合残差仅反映控制点一致性，不等于实地误差。图像局部形变可能使中间位置不准，即使控制点误差为零也不能保证整洞精度。

绝对精度需要独立检验点与实地 GPS/测绘核查。人工按卫星影像选点仍可能有影像偏移、分辨率和地物识别误差。未实测项目保持 accuracy_m 未知和 field_verified=false，不能承诺亚米或米级准确。覆盖范围外拒绝新增地理点，不把人或球车画到一个猜测位置。

## 6. 实现模块与扩展

- `store.js`：格式校验、项目隔离、保存、旧草稿兼容、数据目录读取。
- `catalog.js`：地图选场、在线名称查询、新建、文件与文本导入。
- `projects.js`：GeoJSON 转换、图片资源存储、完整包导出/导入与状态检查。
- `editor.js`：复用原版地图工具，同页自由点位、跨洞测距、GPS、图片编辑桥接。
- `image-editor.js`：通用 Canvas 图片视口、缩放平移、配准、点编辑、路线绘制与定位叠加。
- `holemap-gps/point-workspace.js` / `registration.js`：公共测距与坐标转换能力。

原有泰州高清编辑器作为“兼容入口”保留；新球场走通用图片工具，不需要复制旧页面。新建/导入的项目不需要添加 catalog.json 条目；只有把项目随软件内置分发时才需要增加目录数据。既有高清图片没有重新生成。

## 7. 本次验收记录

实际浏览器（3034）已验证：新建不在内置目录的 3 洞项目；导入带合成测试 PNG 的 2 洞项目；图片放置球车、拖动改坐标、刷新恢复；图片内沿车道模拟距旗由约 310.6 m 变化至 95.3 m；缩放后“全图”恢复且左侧控件保留；完整项目包导出再导入成独立项目，原图资源 ID、4 个配准点和编辑点位恢复。坐标比较浮点差约 3.6e-15 度，不是可测的实地误差。

自动检查覆盖 44 项点位/遥测、12 项既有集成、11 项通用项目，以及 1000 点配准往返测试。包含课程 ID 解耦、内置 2×18 张图片存在、未知字段保留、导入范围与版本拒绝。合成样本只用于流程测试，不混入真实球场基线。

复核命令：`node scripts/check.cjs`、`node --test kingswan/tests/geometry.cjs`、`node scripts/verify-manifest.cjs`。

未完成项：任意名称自动得到准确逐洞几何、自动生成可靠配准的高清美术图、用户上传任意数据的全面兼容、现场定位误差验收、客户硬件协议、云端协作。本次新工具仅在本地整理与验证，没有再次向 GitHub 推送；原项目分发授权仍需明确。
