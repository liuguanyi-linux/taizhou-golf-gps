# 本地网站一体化接入技术文档

版本：2026-09-14。范围：用户自行克隆的 Golf.CC 本地开发实例，不是原作者的线上服务。

## 1. 本次交付与边界

将通用球场制作工具接入本地网站已有后台选场入口。实景地图、矢量虚拟图、高清制图、图片配准、自由点位、多车及跨洞 GPS 测距共用同一份 WGS84 项目。新增后台完整项目存储，避免旧球洞接口只保存固定几何字段、丢失图片和设备点位。

现阶段为开发集成，不是已通过现场验收的导航产品。自动测试通过；登录后的真实浏览器保存、发布、跨设备恢复仍待管理员登录验证。没有把任何客户球场发布到线上，没有推送原作者仓库。

## 2. 用户操作

1. 启动本地网站及其 Go API、PostgreSQL、Redis。使用 `localhost`，不要与 `127.0.0.1` 混用，浏览器登录和暂存按来源隔离。
2. 在 `http://localhost:3030/cn/admin/greenbook` 登录并检索球场；进入已有的球洞编辑入口。
3. 页面跳转到本站 `/golf-tool/holemap-editor/index.html?gb=球场编号&workspace=1&website=1`。首次接入读取原站该球场的位置和现有洞数据；之后优先恢复本浏览器暂存，后台版本仍受冲突检查保护。
4. 使用左侧四步制作流程：检查地图要素 → 生成缺少的高清图 → 编辑本洞／GPS → 交付检查。缺少逐洞划分时先读取公开地图候选要素并审核，或在卫星图上描绘，不能把空洞位当作完成。
5. 自由放置球车、目标点和旗杆，编辑 Tee、点线面或车道；图片模式放点经配准反算回同一 WGS84 数据。选择测距起终点，可跨洞、车对车或车对固定点。
6. 点击顶部“保存到网站后台（草稿）”。这会上传完整项目及内嵌图片，但不改变原前台已发布地图。
7. 核对球场、单位、点位隐私和覆盖范围，勾选发布确认，再点击“发布到本地网站前台”。发布会同时更新原前台兼容几何和完整工具项目。
8. 从“查看已发布项目”验收。公开访问者使用发布版本的本机体验副本，其编辑不会回写后台。需要离线交付时下载完整项目包，而不只是旧版几何 JSON。

“保存本机数据”“保存后台草稿”“发布前台”“下载包”是四个不同动作。生成图片不会隐式发布，也不会上传 GitHub。

## 3. 架构与数据路径

| 部分 | 职责 | 持久位置 |
| --- | --- | --- |
| 网站后台选场入口 | 沿用账号和球场检索 | 原网站 |
| `course-workspace/website.js` | 项目读写适配、版本与单位处理 | 不单独存服务端数据 |
| `website-ui.js` | 明确区分暂存、草稿、发布与冲突恢复 | 浏览器 |
| 编辑／制图／GPS 引擎 | 同一 WGS84 项目编辑、绘图、配准和测距 | localStorage + IndexedDB |
| Go tool-project API | 鉴权、包校验、版本检查、事务发布 | PostgreSQL `golf_tool_project` |
| 原 holemap API | 旧前台仍可识别的点线面、洞信息、距离 | 原 GreenBook 几何表 |
| 公开 tool-project API | 仅返回最后一次已发布完整项目 | 同一项目版本表 |

不是把原网站全部改成新框架。静态工具安装到独立 `/golf-tool/` 命名空间；原 `/holemap-editor/`、`/holemap-viewer/` 文件保留。

## 4. 项目数据契约

完整包沿用 `golf-project/1`，包含 `course` 与 `assets`，未知扩展字段原样保留。后台模式要求：

```json
{
  "format": "golf-project/1",
  "field_verified": false,
  "course": {
    "website_venue_id": "cn0000385",
    "name": "示例球场",
    "coordinate_system": "WGS84",
    "center": [120, 32],
    "distance_unit": "m",
    "holes": [{"n": 1, "par": null, "device_points": []}]
  },
  "assets": {}
}
```

以上坐标仅说明格式，不代表实地球场。空项目可以保存草稿，但没有可发布几何时禁止发布。

- 坐标顺序固定 `[经度, 纬度]`，不可传 GCJ-02／BD-09 并标成 WGS84。
- `device_points` 包括稳定 ID、坐标、类型及来源等扩展信息；具体设备协议见 [主技术文档](TECHNICAL.md) 和 [通用工具说明](GENERIC-TOOL.md)。
- 每洞 `visual`／`visual_previous` 引用图片资产、尺寸、控制点、独立检查点；完整包在后台保存后仍可恢复这些信息。
- 1–72 个不重复洞号；未知 PAR 使用 `null`，不默认伪造 Par 4。
- 旧 API 的 `dist` 是码；首次接入乘 `0.9144` 转米一次。发布旧前台时只转换兼容副本，不改完整项目原始单位。不能靠改单位标签来转换既有数值。
- 经纬度小数位数、拟合残差和算法回算精度都不等于现场 GPS 精度。图片、原始地图或参考点不准确时，精确计算也会产生准确外观下的错误位置。

## 5. HTTP 接口

沿用原 API 的 `{data: ...}` 成功包和错误响应约定。

| 方法与路径 | 权限 | 作用 |
| --- | --- | --- |
| `GET /v1/admin/gb/venues/:id/tool-project` | 原后台账号与管理员角色 | 最新草稿或发布版本 |
| `PUT /v1/admin/gb/venues/:id/tool-project` | 同上 | 新增完整草稿版本 |
| `POST /v1/admin/gb/venues/:id/tool-project/publish` | 同上 | 事务发布完整项目和旧前台几何 |
| `GET /v1/gb/venues/:id/tool-project` | 公开只读 | 最近已发布版本；未发布时 `pack:null` |
| `GET /golf-tool/map-source/golf?lng=...&lat=...` | 公开只读 | 固定范围公开地图查询，不写项目 |

读接口字段：`revision`、`base_hash`、`published`、`pack`。写请求体为完整包；成功响应返回新的版本号和哈希，不重复返回大图片包。

写请求头：

- `Authorization: Bearer <用户自己的登录令牌>`。
- `Content-Type: application/json`。
- `X-Golf-Revision`：客户端读取的最新工具版本号，首次为 0。
- `X-Golf-Base-Hash`：原几何快照 SHA-256；发布时校验。
- 发布还要求 `X-Golf-Publish-Reviewed: yes`，对应 UI 的显式确认。

未登录返回 401；版本或原几何变动冲突返回 409；超过请求体限制返回 413；格式／坐标错误拒绝保存。浏览器不会把令牌发往查询参数指定的 API 地址；默认只使用当前主机，3030 本地开发映射到 8088。公开读取不发送管理员令牌。

## 6. 并发、发布与数据恢复

每次保存新增不可覆盖的版本记录。事务锁定同一 `gb_venue` 行后检查版本，避免两位编辑者相互覆盖。发布另外比较原 holemap 的稳定快照哈希，防止旧编辑器的改动被静默覆盖。

发布事务内：核对双重版本 → 更新原前台几何 → 切换旧公开版本标记 → 插入新公开完整版本。任何一步失败整体回滚。后续保存草稿不会撤换此前公开版本。

遇到 409，先下载本机完整包。需要丢弃本机暂存并读取后台时，使用“读取后台版本（先备份本机修改）”；确认后仅清除此球场相关的逐洞暂存，不清其他球场。该按钮不是自动合并工具。若原版编辑器修改了几何，仍须人工核对并重新接入，不能把哈希校验当成自动解决冲突。

数据库迁移 0139 新建 `golf_tool_project`，主键 `(gb_id, revision)`；部分唯一索引保证每场至多一个公开版本。包以原始 JSON 文本保留，图片随包保存。没有自动历史清理或图片去重；应备份和监控数据库容量。

## 7. 输入和运行限制

- 请求体最多 64 MiB，包括 Base64 图片；最多 144 项图片。
- 后台接受 PNG/JPEG，不接受 SVG、远程图片 URL 或 WebP。独立工具支持的 WebP 请先转为 PNG/JPEG 再保存后台。
- 单图解码后最多 20 MiB、最多 5000 万像素；校验真实图片格式、尺寸和配准点范围。
- 距离字段为数值字典，0–10000；点、线、面、全场车道及设备点校验 WGS84 范围。
- 发布兼容几何数量须为 1–4000。校验通过不表示拓扑、洞号归属、地图授权和实地精度自动合格。
- 公开地图代理仅查询中心 1800 米附近，响应上限 12 MiB，超时 45 秒，缓存十分钟最多二十项。地图来源不可用时明确报错，不把不完整结果当成功数据。
- 生产公网还需反向代理上传限制、速率限制、备份、HTTPS 和账号权限验收；当前开发实例不应直接暴露到互联网。

## 8. 本地安装与接入文件

资源安装：在工具根目录运行 `node scripts/install-local-website.cjs /path/to/Golf.CC`。安装器检查目标是本地源码项目，用 SHA-256 清单管理 `/golf-tool/` 静态文件和 `web-user/lib/golf-tool/` 的两个地图请求模块；拒绝覆盖非安装器管理的目录或已被人工改过的已安装文件。它不安装数据库、Go 接口或整站，也不会清空目标目录。

服务端新增文件位于本地网站：

- `server/internal/data/golf_tool_project_repo.go`：项目存储和事务。
- `server/internal/biz/golf_tool_project.go`：用例层。
- `server/internal/service/golf_tool_project.go`：接口和校验。
- `server/migrations/0139_golf_tool_project.up.sql`、`.down.sql`。
- 对应 service/data 测试文件。

已有文件接点：

- `greenbook_handler.go` 注册公开 GET，并在已有 `authMW`、`adminMW` 内挂载项目管理接口。
- `cmd/api/main.go` 的 CORS 请求头白名单增加上述三个 `X-Golf-*` 头，不扩大来源白名单。
- 后台 `[locale]/(app)/admin/greenbook/[id]/holemap/page.tsx` 修改跳转到 `/golf-tool/`。
- `GreenBookVenueDetail.tsx` 为已有球洞图增加“查看已发布虚拟图 / GPS 工具项目”链接；旧查看器仍只理解旧数据结构。
- `app/golf-tool/map-source/golf/route.ts` 增加只读公开地图代理；`middleware.ts` 仅对该精确 JSON 路由跳过语言页面重定向。

先备份数据库与本地未提交改动，再使用原网站迁移命令 `go run ./cmd/migrate up`，编译 API 并重启自己管理的进程。不要把这里的文件盲目覆盖到另一个版本的原网站。

生产部署默认使用同源 `/v1/` 反向代理；自定义 `window.GOLF_TOOL_API_BASE` 必须在 `website.js` 之前由受信任站点配置设置，且必须同主机名。GitHub Pages 只能托管静态工具和文档，不能运行 Go/PostgreSQL 后台，不能连接访客电脑之外的 localhost。

## 10. 回退、隐私与分发

回退应用时先关闭新入口和项目路由、恢复对应接点，不覆盖其他未提交编辑。迁移 down 故意保留版本表，避免误删项目和图片；完全删除需单独备份及明确确认。回退界面不会自动撤回已经发布的原前台几何，需要恢复发布前数据库备份或核对后的原几何。

发布前检查多车实时位置、客户点位、备注及图片是否适合公开；公开下载无法撤回他人已有副本。工具不会自动上传实时 GPS 日志到 GitHub。

原网站 LICENSE 为专有许可。拥有自己 GitHub 仓库的发布权限不等于拥有第三方源码的公开分发许可。不得把整个克隆网站、数据库、环境配置、登录信息或未经授权的地图影像上传。新增接入实现与说明应单独整理；涉及原版编辑器的完整公共分发需先明确原作者许可。本地集成测试与公共发布是两项独立验收，本文不表示新版本已上线。

## 11. 2026-09-14 公开地图读取故障修复

复现症状：本站地图代理返回 503，底层原生 fetch 直连 Overpass 出现连接拒绝／超时；启用环境代理后还发现默认请求标识可能收到 406，上游偶发 504。原代码把这些不同原因合并成了笼统失败提示。

修复：3034 独立版与 3030 网站版共用 `osm-readonly.cjs` 和 `map-transport.cjs`。专用 HTTPS Agent 读取现有 `HTTPS_PROXY`／`https_proxy` 等环境配置，保留 `NO_PROXY` 规则；不更改全局代理、不改变登录请求、不向地图服务发送网站令牌、不关闭 TLS 校验。不把代理凭据放进错误信息。

使用明确的客户端标识、每次 22 秒超时和 12 MiB 响应上限；上游查询限时 15 秒，502/503/504 最多再试一次，总请求等待约 44 秒。429 不立即重试；连接失败、非 JSON、超时、大小超限和部分结果各自显示原因。只缓存完整有效结果，不自动导入候选要素，不覆盖现有地图。

代理功能依赖 Node 24.5+、22.21+ 或更高主版本；低版本在配置了代理时明确提示升级，不能静默忽略代理。[Node HTTPS Agent 官方说明](https://nodejs.org/api/https.html#new-agentoptions)。代理必须由启动进程的受信任环境提供，浏览器查询参数不能改变代理或目标地址。

验证：网站接口实际读到 21 个公开要素；浏览器在原佘山项目点击同一按钮，成功读取 69 个候选要素并显示确认界面，其中边界内 55 项、范围外 14 项。没有确认导入、覆盖原点位或重新生成原图片。地图回归测试 14 项通过（包括临时 504、429、非 JSON、错误脱敏及代理版本判断），全套脚本与网站类型检查通过。已有现场精度状态不因联网成功而变化。
