# 从球场位置生成可编辑虚拟地图与 GPS 数据

## 使用入口

启动 `node scripts/serve.cjs`，打开 `http://localhost:3034/cn/map/`，搜索球场并接入独立项目。在编辑器左上找到 **生成虚拟图与 GPS 数据**：

1. 点击 **读取公开地图并生成…**。将球场中心坐标发送至公开 Overpass API；不发送设备定位、账户凭据或本机草稿。
2. 在右侧确认球场边界。范围为中心周围 1.8 km，多个球场必须手动选定；没有闭合边界时不自动归属。
3. 检查列表中的洞号、类型与勾选项。点击“定位”查看地图轮廓。`ref` 和 `Fairway1 / Hole 1 / Tee Box1` 等名称只用于建议洞号；没有编号的要素必须手动归属。
4. 点击 **确认生成 N 个要素及参考点**。仅把已确认且不冲突的要素写入本机项目。零候选或未勾选、未归属时按钮灰显并解释原因；没有可用要素时，右侧直接选择洞号并补绘球道、果岭、发球区或球车路线。
5. 在同页切换 1–18 洞，编辑轮廓、放置球车、自定义目标或旗位。在测距下拉框选择起终点，支持跨洞目标。
6. **下载本洞 SVG** 导出坐标驱动的虚拟图；**下载全场 GPS 点位** 导出带来源和精度说明的 GeoJSON；“球场项目”内下载完整项目包保存所有点线面。

已有源数据的洞可直接查看矢量图，无须再次导入。没有几何的洞点击虚拟图时保留实景底图，并提示建立要素，不再展示空绿背景。

生成按钮无反馈与空数据补绘的修复及验证见 [2026-09-14 修复记录](GENERATION-EMPTY-STATE-FIX.md)。

公开数据缺失时，还可试用 [卫星影像辅助提取](SATELLITE-ASSISTED-TRACE.md)：框选单个地物并点击内部，颜色分割得到候选轮廓，人工确认后写入 WGS84。它不是自动识别洞号或全场制图。

## 能生成什么 / 不能保证什么

- 读取公开地图里确实存在的球道、果岭、发球区、沙坑、水域、长草区、击球中线、球车道、旗位。保留原始坐标节点及 OSM 要素 ID。
- 面要素生成一个明确标为“几何推导”的参考点；不能当作实测发球点或当天旗位。未标颜色的发球区不擅自生成黑、蓝、白、红 Tee。
- 不用球道中心线假冒球车路线，不自动捏造球车位置或无数据的洞。
- 不采用范围外要素。不支持的关系、多面等结构暂不导入并统计，不强行摊平。边界穿越的要素需手工处理。
- 不覆盖已有单面 / 主线 / 旗位。重复导入按 OSM ID 检查。同洞同类单面存在多个候选时，默认不勾选，要求用户核对。
- 矢量图是当前点线面数据的可编辑渲染，不是泰州那种高清美术图片。美术图片仍通过“本洞图片 / 配准”绑定，配准通过后才能把图片位置映射为地理坐标。
- 地图矢量和用户描点均非实地测量，`accuracy_m: null`；小数位数不代表准确度。设备实时 GPS 精度也与地图误差不同，交付前需要独立现场核验。
- 距离面板计算两点间地表直线距离，不是沿球车道行驶距离。

## 佘山源数据实例（2026-09-11）

原站 `cn0000160` 返回球场位置但无逐洞几何。公开 OSM 可读到 18 个球道面、17 个 `golf=green` 面、19 个 `golf=tee` 面。

第 8 洞有 `name=Hole 8, golf=tee` 与另一 `Tee 8`，属于需要核对的类型 / 归属冲突。工具保留原标签，不擅自改成 green，也不虚构第 8 洞果岭。默认跳过两个重复 tee 候选，其余 52 个带洞号面要素可建立草稿；额外未编号水域需用户判断归属。

## 实现与数据结构

- `scripts/osm-readonly.cjs`：固定 HTTPS Overpass endpoint；只接收有限经纬度参数，生成固定类型 / 1.8 km 查询，不允许任意 URL 或 QL；45 秒超时、12 MB 上限、10 分钟 / 20 项内存缓存；不转发 Cookie 或 Authorization。只改 Codex 3034，不写原站 3030 / 8088。
- `course-workspace/generator.js`：纯函数解析、范围筛选、候选归属、无损生成；失败时原项目不变。
- `course-workspace/generation-ui.js`：读取、地图预览、洞号 / 类型确认、冲突处理和明确导出入口。
- `hole.map_sources[]`：原始 OSM ID、标签、原始几何、用户确认的类型、未知精度。后续手动编辑当前几何不改变此原始来源快照。
- `hole.device_points[]`：参考点 ID 基于 OSM ID，来源 `derived_osm_geometry`，精度 null，可继续移动。
- `course.map_generation`：来源、许可证、确认的全场边界、生成时间、`map_draft_unverified`。球场边界不冒充每洞边界。
- 独立编辑器不把果岭平均位置自动保存为“旗位”；用户可以明确放置真实旗位或选择现有参考点测距。

离线或 API 失败时显示错误，保留本机项目。此自动读取需要本机 Node 服务；GitHub Pages 静态部署没有该桥接接口。已导出的项目和矢量几何可继续编辑。

## 数据来源与许可

© [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)，ODbL。生成数据保留来源，SVG 提供可见归属文字；公开再分发请遵守对应许可。

类型依据 [OSM 高尔夫地图标签](https://wiki.openstreetmap.org/wiki/Key:golf)；球场边界依据 [leisure=golf_course](https://wiki.openstreetmap.org/wiki/Tag:leisure%3Dgolf_course)。卫星瓦片只作在线参考，本功能不批量下载、重制或打包瓦片。

验证：`node tests/map-generation-test.cjs`；完整回归：`node scripts/check.cjs`。这些检查不等于现场 GPS 精度验收。
