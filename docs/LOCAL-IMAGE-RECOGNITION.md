# 本机卫星地物识别：试验版

## 实际能力与限制

本版本第一次接入真实的 CLIPSeg 推理，不再只有颜色连通提取和外部候选导入接口。流程为：在卫星图框选 → 本机模型产生同类地物掩膜 → WGS84 轮廓候选 → 沿用逐洞归属审核 → 保存后生成矢量 / 高清图与 GPS 参考点。

**不是“输入任何球场名就精准生成 18 洞”的成品。** 模型是通用文字分割模型，没有在本项目的球场标注集上训练或评估。当前实际卫星图测试已出现果岭无可用候选、沙坑响应很弱的情况；失败明确显示，不填充假数据。降低分割阈值会增加误检，不意味着精度变好。沙坑提示使用 `sand`，可把道路、建筑或裸地识别为候选，必须逐项核对。

支持果岭、球道、沙坑和水域候选，每次识别一个类别。暂不自动识别官方洞号、Tee 点、当天旗位和球车道。洞号留空，候选默认不勾选；已有中线可辅助提出归属建议，最终由用户确认。处理选区标记为 `scope_only`，不能冒称真实球场边界。

## 如何使用

1. 打开本地网站的球场工具，接入目标球场的本机副本。
2. 使用“AI 卫星识别（本机试验版）”，或顶部“本机 AI 识别卫星地物”面板。
3. 在实景卫星图放大至 z17 以上，选择类别和分割阈值；默认 0.5。
4. 点“框选卫星图并运行本机 AI”，再点地图上两个对角。留出背景，包含完整地物。
5. 状态显示模型加载、识别、完成或失败；可以取消。移动地图、换底图、换洞时取消旧任务，避免使用失配的像素坐标。
6. 有完整轮廓时，点“查看候选并核对逐洞归属”。先在卫星图检查边界，再选择洞号和类型、勾选要保留的项。
7. 确认后写入本机项目，沿用现有编辑、虚拟图、GPS 和导出功能。既有要素不自动覆盖。

没有候选时，可能是模型没识别到，也可能是轮廓太小、碰到裁剪边缘、带孔或过复杂。界面提供排除统计和模型分数范围。分数既不是准确率，也不是米级误差。不要为“生成成功”而接受错误轮廓。

## 安装与启动

macOS 默认把模型和依赖放在用户缓存目录，网站及 Git 仓库不包含模型权重或 Python 环境。本次机器安装约 578 MB 模型、731 MB 运行环境；不同系统会变化。

```sh
python3.12 -m venv "$HOME/Library/Caches/golf-recognition-runtime"
"$HOME/Library/Caches/golf-recognition-runtime/bin/python" -m pip install -r scripts/recognition-requirements.txt
"$HOME/Library/Caches/golf-recognition-runtime/bin/python" scripts/recognition-worker.py --download
node scripts/serve.cjs
```

默认模型：`CIDAS/clipseg-rd64-refined`；固定版本 `999e0328d9e10b484360c477313983f9afdd7050`。只下载 safetensors 和预处理配置，不加载远程 Python 代码。安装下载需要网络；实际识别使用 `local_files_only=True` 和离线环境标记，不把影像上传模型服务。

其他安装路径可通过启动进程的 `GOLF_RECOGNITION_PYTHON`、`GOLF_RECOGNITION_MODEL` 配置，不接受网页请求指定可执行程序、模型地址或文件路径。运行环境要求 Python 3.12，依赖版本见 requirements；未测试其他 Python / GPU 组合。

### 接入本地克隆网站

运行既有 `scripts/install-local-website.cjs /path/to/local/Golf.CC`，新增：

- `web-user/lib/golf-tool/recognition-local.cjs` 和 `recognition-worker.py`，服务器专用，不放 public。
- `web-user/app/golf-tool/recognition/local/route.ts`，同源识别入口。
- 静态编辑器的识别面板和影像采样脚本。

网站语言 middleware 必须放行 `/golf-tool/recognition/local`，与已有 `/golf-tool/map-source/golf` 一样，不得重定向成 `/cn/...` HTML。当前本地克隆已补充该精确路径；通用安装器不任意重写他人的 middleware，请按此说明核对。

本机接口仅允许 `http://localhost:3030`、`http://127.0.0.1:3030`、`http://localhost:3034`、`http://127.0.0.1:3034` 同源调用。公开部署默认拒绝；GitHub Pages 静态网页不能运行 Python 模型。对外提供识别服务仍需独立部署、鉴权、限额和影像使用权限，不在本次完成范围。

## 数据与精度

- 仅读取被选中的底图瓦片像素，不读取 GPS、编辑图层或网页截图；浏览器 CORS 禁止时明确失败，不用代理绕过限制。
- 每个选区最多 1024 × 1024 像素，最长边按比例缩小；模型内部为 352 × 352。放大输出不能增加地面细节。
- 预处理固定整幅缩放，无中心裁剪。输出概率图恢复为选区像素网格。
- 像素 x 在经度范围内线性映射；像素 y 在 Web Mercator 北、南投影值之间插值，再反投影为 WGS84。不能对纬度直接线性插值。
- OpenCV 轮廓取像素中心并保留凹形；不以矩形或凸包替代。带孔、触边、自接触重复节点和过复杂区域拒绝，不静默丢弃孔洞或连成假面。
- 最多 100 个候选、40000 节点；分割阈值 0.2–0.85。识别不自动写项目。
- 来源保留模型、版本、类别提示、阈值、底图提供商、影像哈希、采样尺寸、范围、投影和诊断。原图不保存到项目或 Git；掩膜不作为实测成果。
- `accuracy_m: null`、`field_verified: false`；不能把模型置信度、坐标小数位数、拟合残差当作实地精度。

## 服务与故障处理

`GET /recognition/local` 返回模型文件是否准备好，不代表模型通过完整推理验收。`POST` 只接受同源 JSON，包含 PNG data URL、范围、类别、阈值和提供商。模型结果以 NDJSON 流返回 progress/result/error。

请求上限 6.1 MB，图片字串上限 6 MB，模型输出上限 2 MB；接收超时 15 秒、推理超时 180 秒。单个服务进程同时只运行一个任务；3030 与 3034 是两个进程，各自限额。客户端取消或断开停止子进程。无远程路径、无任意 shell 命令、无项目数据库写权限。

## 验证

```sh
node scripts/check.cjs
"$HOME/Library/Caches/golf-recognition-runtime/bin/python" tests/recognition-worker-test.py
```

自动测试覆盖输入限制、同源与 Host 限制、不可注入模型路径、掩膜闭合/多区域/孔洞/触边处理、Mercator 映射。合成掩膜测试只验证坐标算法，不证明识别质量。真实卫星影像推理和浏览器进度已实测；仍需多球场人工标注样本评估边界、类型、洞号，最后用独立现场点核验地图精度。

### 本次实际影像验收记录

- 使用独立的“卫星提取验收副本（洞号未核对，不用于导航）”，没有改动正式球场。
- 果岭类别未得到可用候选；部分沙坑选区低响应，另一选区响应较强但触边，均显示失败而未写入。
- 一个较小选区返回 1 个闭合候选，但与可见主沙坑轮廓不一致，**未接受该结果**。它可以进入逐洞审核，洞号留空、默认不勾选、生成按钮禁用。这证明接入与保护流程，不证明沙坑识别准确。
- 新增“查看本次识别输入影像”诊断，可对照模型真正读到的底图；输入中不包含 GPS 和人工标注覆盖层。
- 本机原网站的识别状态接口返回正常，外部 Origin 请求被拒绝（403）。完整的登录后台保存 / 发布流程未在本轮重新验收。
- 2026-09-16 浏览器取消验收：框选实际卫星图启动推理，接口返回 `busy: true`；点击“取消本次识别”后显示“没有写入项目”，接口恢复 `busy: false`，模型子进程退出，服务继续正常响应。要素清单仍只有测试副本原先的沙坑及其参考点。修复了取消已关闭的输出流时可能抛错的问题，并在子进程退出前保持忙碌锁。

结论：当前仅作为可替换模型的试验接入层，不默认替代手绘与已有地图几何。尚不能推荐无人审核地生成客户导航数据。

模型依据：[Hugging Face CLIPSeg 文档](https://huggingface.co/docs/transformers/model_doc/clipseg)、[CIDAS 模型与许可](https://huggingface.co/CIDAS/clipseg-rd64-refined)。模型 Apache-2.0 许可不赋予卫星影像版权；影像与派生数据发布权需单独核对。本次不重新分发权重或底图影像。
