# 卫星影像辅助提取轮廓（试验功能）

2026-09-15，本地工具更新。它补充“公开矢量数据不存在”的情况，但不是全场自动识别或测绘认证。

## 操作

1. 搜索球场并进入独立项目，选择自己已核对的洞号。
2. 打开左侧“从卫星影像辅助提取轮廓（试验功能）”。没有公开地图候选时，右侧空状态也有同名试用入口。
3. 在实景卫星图中放大到单个地物，最低 z17。选择果岭、球道、发球区、沙坑或水域。
4. 点击“在卫星图框选并提取”，在地图点击两个对角，框住整个地物，周围留一些背景。
5. 点击框内地物的内部。颜色容差默认 24；小值更严格，大值更容易连入相邻区域。可改变容差后再次点内部。
6. 对照影像检查青色候选轮廓，确认洞号、类型后勾选确认，再加入当前洞。若不正确，取消并手绘；不要为了得到结果而不断放宽容差。
7. 保存后的轮廓沿用原有节点编辑工具；切换矢量虚拟图、GPS 测距使用同一份坐标。补齐球道、果岭和必要点位后再走高清制图流程。

更换球场、球洞、地图视角或底图会使候选失效，必须重新框选。候选未确认前不会写入项目。已有球道、果岭或发球区不自动覆盖；沙坑、水域追加，但拒绝完全相同的轮廓。

## 实现

- `course-workspace/image-trace.js`：可单测的颜色连通提取和无覆盖写入逻辑。
- `course-workspace/image-trace-ui.js`：读取当前底图可见瓦片的选区像素、预览、确认与取消。
- 采样最长边 512 像素，总计最多 262144 像素。以点击处颜色为固定基准，4 邻域连通，不使用不断漂移的颜色均值。
- RGB 三通道均方距离阈值由容差决定。这是颜色分割，不是识别“沙坑”的语义模型。
- 提取像素边界，只删除共线点，不用凸包填满凹陷。触边、过小、多轮廓、空洞、歧义连接和超过 1500 个顶点的结果拒绝写入，要求调整或手绘。
- 基于当前 Leaflet 地图的容器像素 → 地理坐标转换，每个边界节点保存为 WGS84。异步读取期间地图移动、取消或切换洞号，用序号使旧结果失效。
- 保存 `hole.image_sources[]`：底图 provider、读取时间、缩放级别、选区经纬度、采样尺寸、种子像素、颜色容差、原始轮廓及人工确认标记。
- 保存状态 `image_draft_unverified`，精度始终未知；每个导入面生成一个明确标为“影像提取”的边界参考点，不生成真实旗位或颜色 Tee。

## 安全与精度边界

处理在本浏览器执行，不向模型服务上传图片或设备 GPS，不保存和打包卫星底图副本。像素读取遵守底图服务的 CORS 限制；不能读取时清楚提示，不使用代理绕过限制。缺瓦片不当作地物边缘。

高德沿用原编辑器现有的 WGS84 对齐画布，不重复进行坐标偏移转换。影像源定位误差、拍摄日期、像素分辨率、遮挡、阴影以及采样都会影响结果。屏幕放大和更多坐标小数位均不会提升实地精度。商用或转发提取数据前，使用者仍需核实对应影像服务的数据使用条款。

它不能自动确定洞号、今天的旗位、发球颜色、完整 18 洞或球车路线。车道为线要素，本功能不把提取出的草地面中心线冒充车道。卫星图上存在地物也不保证颜色分割能成功。

## 验收记录

自动测试 `node --test tests/image-trace-test.cjs` 共 7 项：连通边界、凹形保留、相邻独立区域排除、触边/空洞/透明/尺寸限制、坐标转换、确认后只写所选洞、原有编辑及重复导入保护。已纳入 `scripts/check.cjs`。

实际浏览器：在南山可见的一个沙坑上，Esri z17.5、76 × 53 像素选区，容差 24 因空洞被拒绝；容差 40 获得 128 个不同边界节点。候选叠加与可见沙坑位置对应。此结果只证明一次影像辅助提取可用，不代表实地边界准确或该地物洞号已确认。

写入与持久化测试在明确命名为“卫星提取验收副本（洞号未核对，不用于导航）”的独立本机项目完成：保存一个沙坑面和一个边界参考点；刷新后 129 个闭合坐标节点、参考点及来源记录完全一致；可切换矢量虚拟图。未把此测试轮廓写入南山原工作项目，也未发布。
