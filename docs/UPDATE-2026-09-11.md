# 2026-09-11 · 地图选场与原版编辑流程整合

发布状态：本次更新仅在本地完成，尚未上传或部署。原项目 LICENSE 限制未经授权的公开分发；需先确认原版编辑器代码的公开发布授权。已有在线版本不代表这次更新已经发布。

## 本次交付

入口为 `cn/map/`：地图选球场 → 选择洞号 → 编辑球洞图。进入后在同一个页面切换实景地图、坐标驱动的虚拟地图、已有高清图编辑与 GPS 测距。

这是独立静态包中的流程整合，不是朋友的 Golf.CC 全站，也没有复制其账户、预订、人员信息或完整球场数据库。原版 Leaflet / Geoman 编辑器的点、线、面、Tee、果岭旗和车道工具保留。本机使用 3034，不修改 3030、8088 或 Docker。

## 怎样使用

1. 在地图页选择泰州或金沙湾，选择洞号，点击“编辑球洞图”。其他球场可输入名称和城市，点击“在线定位其他球场”，核对候选位置后建立场地；也可导入已有的 WGS84 球场 JSON。
2. 想试操作但不影响自己的草稿，先点“另存副本”。副本有独立的球场 ID。
3. 在左侧填写名称，点“放置球车”或“放置目标点”，然后点击地图。放下的点可直接拖动。Tee、果岭、沙坑和球车道沿用下方原版分类及地图工具栏。
4. 在“测距起点”和“测距终点”选择点位。终点可选择其他球洞的 Tee、果岭或自定义点；两辆车也可互相测距。
5. 实景地图与“虚拟地图 · 可编辑”使用同一份经纬度和同一个地图画布。滚轮缩放由地图管理，不缩放整个网页，左侧操作面板保留。
6. 要演示车行，沿真实车道绘制“本洞球车路线”，点击原版“播放”，测距起点选“本洞路线模拟球车”。不会把球道中线强行当成车道；路线终点由你绘制的节点决定。
7. 要使用设备当前位置，点击“使用实时 GPS”并授权。地图显示设备报告的位置，距离持续更新，不会强制吸附到车道。模拟、手动点和真实设备定位是不同来源。
8. 点击“保存本机数据”，刷新后检查。交付别人前使用原版“导出 JSON（备份）”导出全场数据；点位交付可使用“导出全场点位 GeoJSON”。别人的浏览器不会自动收到你的本机草稿。

## 高清图与矢量虚拟地图的区别

- 泰州：保留已有 18 洞高清图；“高清图 / 配准编辑”在当前页面内打开已有查看器的编辑模式，并传递当前洞号。返回地图时重新读取共享草稿。
- 金沙湾：保留 18 张美术草稿和记分卡；尚无可靠逐洞几何及图像配准，因此高清图只展示，并明确提示不可由像素直接推算准确 GPS。请在实景地图建立真实要素后再做配准。
- 新球场：“生成本洞矢量虚拟图 SVG”根据已经存在的点线面生成图形，附 WGS84 原始数据、EPSG:3857 渲染投影和范围。它不是 AI 美术图生成器，也不会凭球场中心点编造 18 洞布局。

只知道球场名称或中心位置，不足以可靠确定每一洞的边界、洞号、Tee、果岭和车道。定位、几何整理、图像配准、现场独立检验是不同步骤。**本次未完成“任意球场名称自动生成准确的全套 18 洞 GPS 与高清图”。**

## 数据模型与兼容

`course-workspace/store.js` 为本机球场仓库；`catalog.js` 管理地图入口；`editor.js` 扩展现有编辑器，不另建第二套地理画布。

所有原始坐标使用 `[经度, 纬度]` 的 WGS84 数组。导入时若明确标为 GCJ02 等其他坐标系，会拒绝而非静默当作 WGS84。未知字段、已有注册模型与扩展元数据在全场保存时保留；编辑果岭、旗点或 Tee 后清除旧的派生果岭目标缓存，重新计算。

存储顺序：当前浏览器的整场副本优先于磁盘基线，再合并已有查看器的逐洞草稿。键名如下：

```
golfmap.course-workspace.v1.<course-id>
golfmap.course-workspace.v1.catalog
golfmap.gps-draft.<course-id>.hole-<hole-number>
```

点位保存在 `holes[].device_points[]`。旧编辑器的 `cart_test` 在统一点位目录中规范为 `cart`，避免图上有车但测距列表没有车。手动拖动 GPS 导入点时，其来源改为 `manual_map`，设备精度改为未知，不沿用原来的实测精度声明。点位的可复用标识由球场、洞号和本地点 ID 组合。

GPS 快照输入示例（仅示范格式，坐标不是现场验收点）：

```json
{"positions":[{"id":"cart-a","name":"球车 A","coordinate":[120.0722,32.615],"accuracy_m":3}]}
```

也支持 CSV 列 `id,longitude,latitude`。同一 ID 更新本洞已有车辆，不重复创建；可携带名称、精度及合法带时区时间戳。格式错误时会提示，不应把错误记录当成有效 GPS。

新增测距面板使用现有 WGS84 椭球测距模块，显示的是两点地表直线距离，**不是沿道路行驶距离**。道路剩余距离需要可信的路线几何、路线方向及终点定义；本面板不会把直线距离伪装成道路距离。车与果岭旗的距离也不表示球车应驶入果岭。

## 运行、外部服务与隐私

运行 `node scripts/serve.cjs`，本机打开 `http://localhost:3034/cn/map/`。正式共享应使用 HTTPS 发布页或打包文件，不应把 localhost 发给远方用户。浏览器定位依赖安全上下文和设备授权；桌面定位可能误差很大，不能据此判断球场测绘精度。

球场名称查询使用用户主动触发的 [Nominatim Search API](https://nominatim.org/release-docs/latest/api/Search/)，不做输入自动补全，限制连续请求并缓存结果。查询名称发送至外部服务；当前设备 GPS 不随名称查询发送。第三方地图瓦片加载会请求相应服务商。离线、限流或网络失败不影响已经缓存于浏览器的草稿，但在线影像与定位搜索可能不可用。

本版本没有车辆消息服务器、远程多人共享草稿或后台自动发布功能。导出的真实车辆轨迹和位置可能涉及隐私，请不要直接提交到公开仓库。当前公共包只包含磁盘已有基线、代码和图片，不包含验收浏览器里的本机测试点。
