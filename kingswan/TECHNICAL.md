# 金沙湾地图编辑与 GPS 工作台

版本：2026-09-10，开发预览；球场 `cn0000386`（常州金坛金沙湾）。

## 当前交付边界

本版本包含 18 洞虚拟底图**视觉草稿**、记分卡数值、场地参考范围，以及同页编辑 / 设备预览代码。没有预置已经测绘、逐洞核对的 Tee、果岭、球车道，也没有给 18 张虚拟图预先赋予可靠的地理配准。

卫星影像可见不等于逐洞几何已存在。旧后台金沙湾有球场记录，但本次只读核查未找到保存的逐洞几何。全场参考范围仅用于定位，不作为逐洞边界或测量依据。

功能测试、配准检查和现场 GPS 精度验收是三个不同阶段。当前代码与数据不能作为导航安全、球车自动控制、测绘认证或精准测距承诺。

## 使用流程

1. 通过 HTTP 本地服务或 HTTPS 网站打开本目录 `index.html`。不建议直接双击文件。选择球洞，点击“定位金沙湾 / 本洞”。未绘制本洞要素时会定位全场，不能自动知道每一洞在哪里。
2. 在卫星图辨认本洞，选择球车、Tee、果岭旗或参考点，填写名称后单击放置。点保存为 WGS84 `[经度, 纬度]`。选中对象可查看稳定 ID、修改经纬度、拖动节点。
3. 画球车道或行驶路线时，从起点按行驶顺序逐个点击道路拐点，点击“完成线 / 面”。区域至少三个不重复顶点，不支持带内洞的多边形。路线方向就是节点顺序，不会自动反转或用球道中线替代。
4. 配准虚拟图：点击“添加对应点”，先点卫星图地物，再点虚拟图同一地物。至少三点不共线，建议五点以上，覆盖起点、终点、中段和左右两侧。添加独立检查点，核对未参与拟合的位置偏差。不能为了让拟合成立随意配对不同位置。
5. 未配准时仍可在虚拟图放点、绘线和面，但仅保存像素草稿，不进入 GPS 测距和地理 GeoJSON。配准后，仅控制点凸包覆盖内可转换；越界不会外推成假 GPS。
6. 点击顶部“设备预览”，不打开第二个编辑网页。选择起点和目标，可跨洞、球车对球车或球车对 Tee / 果岭旗。起点需要有效地理坐标；像素草稿不会出现在 GPS 点列表。
7. “沿本洞路线模拟”需本洞球车与本洞 `cart_route`，按路线节点顺序行驶，100% 停在道路终点，不穿越草坪跳到旗位。“返回已保存位置”清除动态位置，方便继续拖动静态标记。
8. 滚轮以地图视窗中心缩放；拖动平移。“虚拟图复位”恢复整张图。顶栏和独立滚动的左侧控制区不参与图片缩放。
9. 草稿自动存本浏览器；换设备、清理浏览器或更换域名前先“导出全部数据”。导入自己的完整包可恢复控制点和像素草稿。部署站点不自动同步各人的编辑结果。

图片有局部形变时，全局配准即使残差小也可能局部错位。此时应修订图片或采用经核验的更精细映射，不能仅调三个控制点后宣称任意点都准确。

## 数据结构与兼容边界

`baseline.js` 包含 18 洞 PAR、难度、五色 Tee 记分卡码数、图片尺寸与 SHA-256、场地参考范围。GPS 就绪标志为 false，初始设备点和路线为空。第 2 洞白 Tee 原记分卡为 383 码，攻略为 363 码，差异保留；码数不是 GPS 测距结果。

编辑状态 `kingswan-editor/1`：

```json
{
  "schema_version": "kingswan-editor/1",
  "course_id": "cn0000386",
  "features": [],
  "holes": [{"hole": 1, "controls": [], "checkpoints": []}]
}
```

实际文件必须包含 1–18 洞唯一记录，上例只展示结构。

地理要素使用 GeoJSON `Feature`：稳定字符串 `id`，`properties.hole` 1–18、`kind`、`name`、`source`、`registration_quality`、`field_verified:false`，以及 Point / LineString / 单外环 Polygon。`pixel_geometry` 是图片坐标，原点在左上角，x 向右、y 向下；它不是 WGS84。

主要类型：`cart`、`reference`、`tee_black/gold/blue/white/red`、`flag`、`green_middle`、`cart_route`、`cart_path`、`hole_perimeter`、`green`、`bunker`、`water`。每日旗位应与果岭中心区分。

导出 `golf-point-workspace/1` 包含：

- `course_id`、`coordinate_system:WGS84`、`coordinate_order:[longitude,latitude]`、距离单位米、生成时间与未验收提示。
- `geojson`：只含非空地理几何。仍可能是人工拾取或配准估算，不能因为在此字段内就当成实测。
- `holes[].registration`：对应点、检查点、拟合模型、覆盖范围与质量标志。
- `workspace`：完整编辑状态，保留尚未转地理的像素草稿。
- 不包含浏览器本次会话的实时车辆轨迹或定位授权。

独立 GeoJSON 导入必须带 `course_id:cn0000386`、`coordinate_system:WGS84`。重复 ID 拒绝覆盖。其他球场数据拒绝导入；绝不把泰州坐标直接套给金沙湾。

本模块与泰州共用 WGS84 / GeoJSON 概念，但**不是旧编辑器浏览器草稿格式的直接替代**。接入客户现有系统时应根据上述字段做适配；不能承诺把任意旧格式直接导入就能运行。

## 设备位置接入

先在编辑器创建具有地理坐标的球车，记录界面“对象 ID”。位置不是新建永久参考点，而是更新该 ID 的会话内动态状态。可在设备预览展开“接入球车位置 JSON”输入，也可由同页业务代码调用：

```js
window.GolfDevicePoints.updatePositions([{
  id: '替换为已创建球车的对象 ID',
  hole: 1,
  coordinate: [119.326, 31.747], // 仅格式示例，不是已测量球车位置
  timestamp: new Date().toISOString(),
  accuracy_m: 5
}]);
```

调用返回 `{updated:数量}`。检查重复/未知 ID、洞号不匹配、非数值/越界坐标、缺失时区、负精度、乱序旧位置及超过当前时间一分钟的未来位置。一次批量校验失败不部分应用。多台球车需各自独立 ID。超过 30 秒显示过期提示；没有精度信息显示未知，不能默认为精确。

`hole` 当前须与球车基线所属洞一致；本版不会自动识别球车进入下一洞，跨洞行驶需业务侧明确管理归属。这是同页 JavaScript 接口，**不是 HTTP 接收服务或已接好硬件的 WebSocket 服务**。外部设备需要在自己的系统中接入定位流并调用接口；静态网站不会自动收取远处设备数据。

“使用实时 GPS”调用浏览器定位，必须用户授权，通常需 HTTPS 或 localhost。精度取决于设备与环境；未取得 GPS 不回退为假位置。图上覆盖外不强行吸附到道路。停止定位保留最后位置；“返回已保存位置”同时停止定位/模拟并清除动态状态。

## 测距与配准算法

- 直线距离为 WGS84 经纬度上的球面 Haversine 地表距离估算（平均地球半径 6,371,008.8 m），不是高程修正距离、椭球测绘距离或道路长度。本版与旧模块可能存在数值方法差异。
- 路径长度累计各折线段距离。当前点投影到路线后显示剩余路线长度，并单独显示距路线的偏移；偏离道路时此投影数值不是完整可行驶距离。
- 路线终点到目标的直线距离单独列出，不能把它当作存在一条连通道路。用户应标绘实际球车道，而非击球中线。
- 图像配准采用局部米制坐标上的最小二乘仿射变换，检查重复点、近共线、奇异变换、超过 10 km 的控制点跨度；使用控制点凸包限制正反变换。
- 拟合 RMS 与独立检查点偏差分开。三点仿射可得到接近零的拟合残差，但不能由此推断实地精度；全程 `field_verified:false`。

## 工程结构与安全

- `index.html / workspace.css / workspace.js`：新增的静态编辑界面、状态管理、地图与定位交互。
- `geo.js`：不依赖浏览器的几何与校验算法。
- `baseline.js / assets/`：生成后的基础数据与 18 张视觉草稿。
- `vendor/`：Leaflet 1.9.4，许可保留在 `LICENSE-Leaflet.txt`。
- 场地参考范围：© OpenStreetMap contributors，ODbL；卫星瓦片署名显示在地图内。瓦片在线加载，不随下载包打包。
- 不连接或修改旧后台数据库。不包含第三方攻略原图、微信照片、个人文件路径或用户实时位置记录。
- localStorage key：`kingswan-cn0000386-workspace-v1`；`?qa=1` 使用独立测试 key 并显示“非实地数据”，不会污染正常编辑草稿。
- 导入为 JSON 数据解析，不执行用户脚本；标签按文字显示。完整包导入会替换当前浏览器工作状态，可撤销本次操作，建议先导出备份。
